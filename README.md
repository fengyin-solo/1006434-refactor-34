# 生活垃圾焚烧发电厂运行管理平台

面向垃圾进厂计量、垃圾池管理、焚烧炉与余热锅炉运行、汽轮发电机组、烟气净化与在线排放监测、飞灰固化与炉渣处理、渗滤液处理、设备点检检修与值班交接的一体化生活垃圾焚烧发电厂运行管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `waste-to-energy-plant:entries` 这一项，或调用 `resetModule(模块)`。

## 交接班超时口径（列表 / 值班看板 / 运营概览统一）

交接班超时只有一份实现，避免三处各算各的：

- 唯一数据源：值班班组、班次、排班起止、交班/接班人员集中在
  `frontend/src/data/shift-roster.ts`（值班花名册）。
- 唯一算法：`frontend/src/domain/shift-handover.ts`。交接截止时刻 = 花名册里**交班人员**的排班下班点
  + 15 分钟办理宽限（白班 20:15、夜班次日 08:15）。
- 唯一取数口：`listHandovers()`（交接班列表）、`loadShiftBoard()`（值班看板）、
  `loadOverview()`（运营概览）内部都先跑 `reconcileHandover()`，三处看到的是同一份结论。
- 办结即冻结：记录进入「已交接 / 有遗留」的那一刻，把超时结论（准时/超时、截止时刻、超时分钟、
  办理用时、判定时间）回写到交班台账并标记冻结。**有遗留事项不会再算一遍超时**，历史记录以后也不
  回头重算，哪怕排班或时间字段被改；老台账里没有结论的办结记录，首次打开时按当时数据补算一次后冻结。
- 办理中（待交接 / 交接中）不冻结：超时随当前时间滚动，结论从「办理中」切到「超时」时才刷新判定时间，
  避免每次打开都写一次存储。
- 花名册查无排班（班组/交班人员都对不上）判为「未排班」，不臆造截止时刻。
- 同一张交接单（交接编号相同）重复提交只记一次：返回已存在记录并提示，不再新增、不再重算。

校验：`cd frontend && npm run verify:shift`（13 项算法断言 + 8 项服务断言，纯 Node 可跑）。
